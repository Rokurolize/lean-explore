● パス変換の仕組み

  1. MSYS2のパス変換

  Git BashはMSYS2ベースで、独自のパス変換レイヤーを持っています：

  - Windowsパス: C:\Users\id374
  - MSYS2内部: /c/Users/id374
  - マウントポイント: C: → /c

  2. 実際の変換確認

● 動作する理由

  1. 自動パス変換

  # MSYS2が自動変換
  /c/Users/id374 → C:\Users\id374

  2. uvの内部処理

  uvは引数として受け取った/c/Users/id374/mcp-tools/lean-exploreを：
  1. MSYS2環境で受け取る
  2. 内部でWindowsパスC:\Users\id374\mcp-tools\lean-exploreに変換
  3. Pythonプロセスに正しいパスを渡す

  3. 環境変数の影響

● まとめ

  なぜ/c/Users形式が必要で動作するのか：

  1. MSYS2の仮想ファイルシステム: Git BashはMSYS2ベースで、Windowsドライブを/c, /d等としてマウント
  2. 自動パス変換: MSYS2は内部で/c/Users/... ↔ C:\Users\...を自動変換
  3. プロセス間通信:
    - Git Bash内では/c/Users/...
    - Windowsプロセス（uv, Python）にはC:\Users\...として渡される
  4. 互換性レイヤー: MSYS2がUnix風パスとWindows風パスの橋渡しを行う

  つまり、Git Bash環境特有の機能により、Unix風パスでもWindowsアプリケーションが正常動作するのです。
